# Development PCM application surface and trusted binding

The development-only `/voice-lab` now contains the actual Gemini PCM panel, separate from the fixed text rehearsal and OpenAI WebRTC panel. The application also registers the authenticated `/api/voice-pcm-evaluation/capabilities` route and the dedicated PCM WebSocket upgrade owner. **The default application installs no approval source, credential source, SDK factory or provider binding. It remains disabled even with the PCM flag enabled. Production cannot compose this runtime.** No keys or approval records were created, and no provider, microphone or patient use occurred in development of this slice.

## Current application behavior

The panel checks server capabilities and requires a supported HTTPS browser. A disabled or incomplete configuration cannot request a microphone or create a socket. After explicit fictional-audio consent it uses the actual PCM controller, AudioWorklet and WebSocket path. Start is deduplicated synchronously. Stop or consent withdrawal requests local shutdown before awaiting cleanup, clears captions and suppresses stale results. Language/account/role changes, authentication transitions, page hiding and unmount dispose the old session. Speaker and microphone controls are independent. Captions remain provisional source-language fragments, not translations, clinical evidence or proof of played audio. Riko remains the separate Nigerian-English TTS narration reference; Live uses Zephyr and does not claim equivalent accent quality.

Local Stop propagates the media graph's actual cleanup receipt. Failed track shutdown, unconfirmed audio-context closure and an unresolved microphone prompt are surfaced instead of being described as confirmed release. Pending permission results are stopped if they arrive after cancellation. Hardware-level shutdown, browser memory erasure, provider retention and final usage are not inferred from the UI.

Automatic socket, device and AudioWorklet failures now retain the same local cleanup receipt as an explicit Stop. The panel waits for that bounded cleanup and shows microphone/context uncertainty even when the transport failed before the tester pressed Stop. Repeated Stop returns the retained result rather than replacing a failed release with a new empty success. A late result from an older session cannot overwrite a replacement session. Reentrant graph callbacks share one cleanup promise, so a terminal event is not mistaken for completed audio-context closure. A retained pending-permission receipt remains conservative after a later stream is stopped; later lifecycle observations provide that additional evidence.

If an interruption or speaker mute cannot stop or disconnect queued playback, the graph now ends the local session instead of accepting another audio turn. It requests microphone shutdown and context closure, preserving uncertainty when closure fails. A delayed speaker-state callback cannot replace the terminal failure with a muted/connected status. Tests cover these failures with fictional Web Audio objects; audible device behavior remains unverified.

Within one panel lifetime, unresolved cleanup from any earlier session remains visible through availability refresh, new consent, replacement speech and a later clean Stop. A clean replacement receipt does not establish release of an older device. Only constant-size concern flags are retained, not media, captions or session identities. Late cleanup can update this separate warning without changing the replacement's phase or captions. These are conservative notices, not evidence of current hardware state; replacing or closing the panel does not itself prove that the browser released hardware.

## HTTP and WebSocket identity correlation

The application HTTP client may authenticate with a bearer token while a browser WebSocket uses cookies. The capabilities response therefore includes the verified actor ID and a SHA-256 correlation label derived from the server-verified user, session family, credential epoch and token expiry. The panel requires that actor to equal its current user. The browser requests one fixed-form WebSocket subprotocol, `doctarx-pcm-v1.<label>`; the server compares it with the authenticated cookie session before gateway admission or provider creation. The WebSocket-ready permit repeats that identity, which the browser also checks before asking for a microphone. Different users, families, epochs or token expirations fail closed. Neither the label nor any token is placed in the URL.

This label is **not an authentication token**, grants no access and replaces no server checks. Neither raw tokens nor session-family identifiers are returned. Token refresh between capability loading and socket admission can require a new availability check rather than silently connecting with a different session.

## Coordinated shared upgrades

Socket.IO is configured with `destroyUpgrade:false` together with `installBoundedUpgradeCleanup`. The companion preserves Engine.IO's one-second cleanup for unknown, unwritten upgrade sockets while excluding Socket.IO's own path. A voice admission may register a server-only ownership record with a separate hard deadline of at most five seconds. Client headers or frames cannot create that record. A delayed authenticated voice handshake can therefore finish without Socket.IO destroying it at one second; unowned paths still close. Owned admission data/FIN handling, payload limits, exact origin checks and actual-socket TLS verification are unchanged. The main server closes the PCM runtime before database shutdown.

Tests use real Socket.IO, its real client, the existing OpenClaw adapter and real loopback WebSockets to check coexistence, slow admission and unknown-path cleanup. This does not verify production reverse-proxy/TLS behavior or every possible third-party upgrade handler.

## Explicit trusted composition

`createVoicePcmRuntime` accepts an optional trusted composition only in development/test with the evaluation flag. It must provide:

- A `sessionPool` for the existing read-only PostgreSQL current-account/session snapshot adapter.
- An `evaluationId`, immutable Google/model/account/project/region/terms/retention binding, and `readApprovalSnapshot` returning current consistent evaluator, language-specific fictional consent, processor and budget records. The existing evaluation policy checks all scopes and expirations. No approval-writing API or database migration is introduced here.
- A credential enrollment reference, a trusted `readCredentialSnapshot`, a read-only credential accessor and a trusted synchronous SDK client factory. None has an environment, browser-storage or global-network fallback.

The application now requires `free_tier_only` approval. The spending record must explicitly allow zero charge (`limitMinor: 0`) and a separate verified `providerBilling` record must match the provider/account/project/model/processing binding, identify its source evidence, and report Free Tier eligibility, model availability and billing disabled. Missing, stale, revoked, paid or ineligible evidence is denied before reading the credential. The authority is reread on active leases; loss of eligibility requests local and provider shutdown. A positive budget, a paid-project zero cap, a Studio login or a successful model listing cannot substitute for this evidence.

**No authoritative Google billing/eligibility adapter is supplied.** Billing-disabled status alone cannot prove eligibility. Evidence freshness cannot be manufactured by updating the timestamp of an old UI observation. Polling is not a provider-side spending guarantee against an external billing change between checks. This code therefore cannot currently establish a no-charge live connection. See [the secure connection checklist](GEMINI_FREE_DEMO_CONNECTION.md).

Credential enrollment snapshots must match the configured processing binding, identify the exact credential reference and revision, have verified/unrevoked status, carry a canonical SHA-256 key fingerprint and current observation/validity timestamps. The supplied key is fetched only after a valid enrollment read and is hashed locally; a mismatch prevents SDK construction. Enrollment is reread after the key fetch to reject concurrent revocation or revision changes. Cancellation during those reads prevents a later SDK create. Secret/error text is not returned or logged. Reads are timed out, and unfinished underlying operations retain bounded slots until they actually settle.

The gateway pins the approved credential reference/revision/fingerprint for its session. A later rotation cannot silently approve continued use of the old credential. Background revalidation closes the peer and initiates provider teardown when that enrollment changes. Provider accounting and durable crash reconciliation remain separate.

**Fingerprint equality only matches a key to trusted enrollment metadata.** It does not prove that the reviewer verified the key's vendor account/project, that the SDK endpoint enforces the recorded region, or that a retention agreement applies. A real approved enrollment source and concrete approved SDK/account integration still need to be supplied and verified. The existing Google Developer API clinical-use restriction remains unchanged. Budget records remain approval metadata, not an atomic reservation or a proven spending cap.

`geminiDeveloperClient.js` provides an inert, **test-only comparison factory** for a separately installed and reviewed `@google/genai` constructor. It pins the Developer API mode, HTTPS Google endpoint and API version rather than merging caller options or relying on ambient endpoint selection. Its only exposed operation accepts one of the three fixed fictional Live configurations. It rejects assumed regional processing; `provider_global` is an explicit absence of a regional residency guarantee. This factory refuses development/production and is not installed by the application. No SDK is imported automatically. Unit tests use a fictional constructor; a separate offline check runs the actual pinned official SDK with all network calls replaced or blocked. The official SDK itself may inspect environment defaults even when explicit constructor settings take precedence.

The offline test of `@google/genai` 2.32.0 validates three-language setup serialization, PCM input/output, interruption and post-setup closure. It also confirms that the SDK keeps its pending WebSocket private until setup completes, so this factory cannot immediately close a hung pre-setup socket. The existing transport reports that uncertainty and closes a late returned handle, but that is not sufficient for live activation. The SDK emits a double-slash WebSocket path whose remote acceptance was not checked. No real provider connection occurred.

`geminiOwnedWebSocketClient.js` is the unmounted development/test candidate instead. It takes a reviewed Node `ws` constructor, pins the canonical Google WSS endpoint, rejects redirects and invalid TLS, disables compression, and bounds handshake time, lifetime, frame size/JSON complexity and send backlog. It retains the socket from construction and returns its session handle immediately. Stop terminates CONNECTING sockets, or requests graceful close on OPEN sockets with a 250 ms termination fallback. Only a real close event confirms closure; termination requests and exceptions do not. There is no key lookup, reconnect, resumption, arbitrary prompt, tool or alternative endpoint.

Its three-language setup and realtime input frames exactly match the actual pinned SDK in the offline harness. Actual Node `ws` loopback tests cover a pending HTTP upgrade, OPEN waiting for setup, and a peer that never acknowledges close. Application composition tests also traverse JWT authentication, zero-charge policy, enrollment binding, this connector, the PCM controller and synthetic browser objects. These tests establish local software and socket lifecycle behavior, not Google's acceptance, final provider accounting or real speech quality. The direct connector remains unmounted until the unresolved approval, credential, billing and HTTPS/device gates are met.

## Evidence and remaining real-demo work

An optional [local lifecycle-observation wrapper](VOICE_LOCAL_OBSERVATIONS.md) can now collect metadata from the actual PCM controller/audio graph in an explicitly authorized harness. It is not installed by the application. Its snapshots do not record audio/captions or prove audible output, consent clicks, language quality or provider closure.

Executed tests compose actual JWT verification, current-session checks, authenticated HTTP capabilities, identity correlation, bounded shared upgrade routing, the real runtime/policy/credential-binding modules, browser controller and PCM graph. All three languages traverse that software chain. Database rows, approval/enrollment records, credential values, browser devices and SDK I/O are fictional doubles. React server rendering verifies static panel markup; lifecycle helpers are exercised independently. No rendered-browser interaction, real audio, provider connection or native-speaker acceptance is established by these checks.

Before a genuine spoken demonstration: supply approved authoritative records and a verified existing credential/SDK binding; establish the account's permitted usage and spending controls; exercise the HTTPS browser/proxy/device path; verify actual session termination; and record fictional spoken-input, interruption, Hausa/Igbo/Yoruba and Nigerian-accent narration evidence with human listening review. Do not present the existing typed-input Google Studio greetings or synthetic automated checks as that demonstration.
